# Review method and limits

The preparation uses three explicit review perspectives performed by the same assistant: source/invariant review; portability/publication review; adversarial reviewer-2 challenge. They are not three independent people or an institutional committee.

Material findings addressed: original oracle required private paths; public data needed explicit sanitation provenance; CLI-only coverage must not imply standalone SHA256 coverage; two controlled command exits are not two started interruptions; source-only distribution must not imply a turnkey installer; a native AERA bridge is not Linux PID1; remote main and v0.2.2 tag differ; original owner licensing declaration is release-specific.

The passive checker's mutation tests attack rehashed semantic defects as well as ZIP/JSON integrity. Fresh extraction checks test relocatability. The frozen runtime and old campaign are not reexecuted. AI reviewers cannot supply independent scientific validation. Receipt hashes authenticate bytes only, not authorship, host honesty or the truth of unobserved events.
